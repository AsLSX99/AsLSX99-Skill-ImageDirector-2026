# 08 模型方言层：同一份画面圣经，翻译成各家听得懂的话

> 产出：目标模型的投放提示词（含参数、负面框、长度控制）。这层解决"绑定 GPT 还是做通用"的纠结：**语义层七模块人人一样，方言层各说各话。**

## 总原则

```
画面圣经（7 模块语义）──翻译──> 方言提示词（按目标模型的吃法）
```

- GPT Image 系：吃**自然语言长描述**——七模块按原文顺排效果最好，这就是"它效果棒"的原因：它对结构化自然语言的指令跟随最强。
- 其他模型不是效果差，是**吃法不同**：给 MJ 喂长散文、给 SD 喂没有质量词的白描，都是用错了方言。

## 各模型方言表

### GPT Image 系（自然语言直出）

- **格式**：七模块按序写成连贯段落/编号段，不拆标签
- **长度**：200–500 字充分展开，可以写细节
- **负面**：转写成正向句尾——"避免五官变形、手指异常…"直接放末尾（它没有独立负面框，但听得懂）
- **改图**：不变量声明必带（见 07 第三节）
- **画幅**：写进正文（"9:16 竖版"）
- **要点**：指令跟随强，可以直接说"只修改 X，其余保持不变"

### Midjourney

- **格式**：短语化——把七模块压成逗号短语，主体放最前
- **长度**：主体+风格+构图是核心，材质细节挑 2 项；过长会被截断（有效注意力在前段）
- **参数**：画幅 `--ar 9:16`，风格强度 `--stylize 60–250`，负面用 `--no 手指畸形,偏色`
- **负面**：用 `--no` 参数，别写进正文
- **要点**：它偏"意象合成"，布局描述（右侧、留白 40%）遵从度中等，关键布局靠 `--ar` + 主体方位词

### Stable Diffusion / FLUX（标签流）

- **格式**：质量词 + 主体 + 场景 + 风格 + 细节，逗号标签堆叠；语序重要（靠前权重高）
- **开头质量词**：`(masterpiece:1.2), best quality, highly detailed`（FLUX 对质量词敏感度低于 SD，可精简）
- **负面**：**必须用独立负面提示词框**，把 07 的清单原样填入
- **权重语法**：`(关键词:1.3)` 强调，`(关键词:0.6)` 弱化
- **要点**：它吃"标签密度"，七模块都要有对应标签；自然语言长句反而降效

### 国产对话生图（即梦/可灵/豆包/可图等）

- **格式**：中文自然语言，七模块连贯成段，接近 GPT Image 但更短
- **长度**：100–300 字；过长模型会只抓前半段
- **负面**：段尾"避免…"一句；部分产品有独立负面框则填框
- **画幅/比例**：多数用界面参数设置，正文写一遍也无妨
- **要点**：对中文语境细节（旗袍盘扣、水墨）理解好；复杂长描述建议分"主体段+风格段"两段发

### 通用兜底（未知模型）

按 GPT Image 方言写自然语言版 + 从 07 挑 3 条负面压成一句——这是兼容性最高的最小格式。

## 翻译检查表（从圣经到方言时过一遍）

- [ ] 七模块在方言里都有落点（或被有意取舍，注明取舍理由）
- [ ] 画幅到了正确位置（正文 or 参数 or 界面）
- [ ] 负面约束到了正确位置（框/--no/句尾）
- [ ] 长度符合该模型区间（GPT 200–500 字 / MJ 短语 / SD 标签 / 国产 100–300 字）
- [ ] 权重/参数语法正确（`--ar`、`(x:1.2)`）

## 换模型的工作量

语义层不动，只重跑本层翻译——**换模型不重写画面圣经**，这正是双层架构的价值。
