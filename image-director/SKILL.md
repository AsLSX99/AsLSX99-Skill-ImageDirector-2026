# AI 生图导演（Image Director）

模型负责生成，你负责审美和设计。真正拉开差距的从来不只是模型，而是**你有没有能力把脑海中的画面描述清楚**。这条工作流把"描述清楚"拆成七个必答模块，再按目标模型切换说法——别再把 AI 绘图当抽盲盒。

## 双层架构（本 Skill 的核心设计）

纠结"绑定 GPT 还是做通用"是个伪命题，答案是分两层：

```
语义层（模型无关）：7 个模块 = 必须交代清楚的 7 类信息
方言层（按模型切换）：同一份语义，翻译成目标模型最听得懂的说法
```

- **语义层永远不变**：不管是 GPT Image 还是 FLUX，画面信息就这 7 类，缺哪类哪类失控。
- **方言层决定效果上限**：GPT Image 吃自然语言长描述（所以按它写的效果最棒）；Midjourney 吃短标签+参数；SD/FLUX 吃质量词堆叠+独立负面提示词框；国产模型（即梦/可灵/豆包）吃中文自然语言。

**先按语义层把 7 模块填满，再交给方言层翻译**——这样一份方案通吃所有模型，换模型不重写。

## 何时进入本工作流

- 要生成/修改一张图（人物、海报、写真、产品图、头像、插画）
- 出图翻车：变形、构图歪、风格不对、颜色脏、手指错
- 有参考图要保持人物/产品一致
- 用户描述了画面但缺模块，或提示词写了结果不对

缺的模块用默认值补齐继续（画幅默认 9:16、风格默认电影摄影），一次只追问最关键的一个问题：**目标模型是哪个**（决定方言层）。

## 七模块工作流

按顺序过一遍，每模块产出一句话级别的明确描述（不是堆形容词）：

| # | 模块 | 回答的问题 | 参考文档 |
|---|------|-----------|---------|
| 1 | 主体设定 | 谁/什么，必须保留哪些细节 | `references/01-subject.md` |
| 2 | 场景与动作 | 在哪、正在做什么、与环境如何互动 | `references/02-scene-action.md` |
| 3 | 视觉风格 | 到底是哪一种"高级感" | `references/03-style.md` |
| 4 | 构图与镜头 | 画幅/景别/机位/布局 | `references/04-composition.md` |
| 5 | 光影与色彩 | 光从哪来、什么色调、禁止整图偏色 | `references/05-light-color.md` |
| 6 | 材质与细节 | 皮肤/服装/头发/环境的可触摸质感 | `references/06-material-detail.md` |
| 7 | 负面约束 | 哪些绝不能出现；改图时哪些必须不变 | `references/07-negative.md` |

万能公式：

```
主体设定 + 场景动作 + 视觉风格 + 构图镜头 + 光影色彩 + 材质细节 + 负面约束
```

**不是每张图都写成长篇大论**——关键是把影响结果的细节交代清楚。单模块一句话也行，但 7 个模块都要有存在感；只写"一个漂亮女生"等于把 6 个模块交给模型瞎猜。

## 执行顺序

1. **填语义层**：按 01→07 过七模块，产出一份《画面圣经》（模板 `assets/templates/prompt-template.md`）。有参考素材的（人物/产品/风格图）在此登记"各负责锁什么"。
2. **选方言**：读 `references/08-model-dialects.md`，按目标模型把画面圣经翻译成投放提示词（含参数、负面框、长度控制）。
3. **投放与检查**：生成 → 按 `references/09-troubleshooting.md` 症状表定位是哪个模块失守 → 只改那个模块重新生成，不整篇重写。
4. **迭代**：同一组图保留命中的一版提示词作为基线，之后每次只动一个变量。

## 质量底线（出图后的检查顺序）

1. 主体没变形（五官、手指、肢体）
2. 构图符合 4 要素（画幅/景别/机位/布局）
3. 风格没串味（说好 CCD 就不能出时尚大片感）
4. 光影有层次、色彩没整图偏色
5. 材质看得见（毛孔、发丝、织物肌理）
6. 没出现负面清单里的东西

任何一项不过 → 对照 09 症状表找到失守模块 → 单点修改重生成。

## 交付物

- 画面圣经（7 模块全填，含参考素材分配）
- 目标模型方言版提示词（可直接粘贴，含参数与负面框）
- 抽卡记录：命中版本标记为基线，失败版本注明失守模块
